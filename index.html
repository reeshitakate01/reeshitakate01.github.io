    project 01 · solo · live on AWS

    VulnScan Pro

    A web vulnerability scanner that crawls a site, runs 15 security checks and grades it A to F.

    problem
    Web apps ship with known, preventable flaws, and checking by hand doesn't scale.
    what I built
    15 scanner modules (XSS, SQLi, CORS, CSRF, TLS, DNS and more), a scoring engine and a Flask API with auth and rate limiting. A scanner is only useful if people trust it, so I kept false alarms low, made it SSRF-safe and tied every finding to a fix.
    result
    Findings mapped to OWASP Top 10, CWE and CVSS, exported as PDF, JSON or SARIF. 52 tests run on every push.

    Python · Flask · SQLAlchemy · Docker · GitHub Actions · AWS

    project 02 · team of 4 · I owned the ML

    SAGE

    A browser extension that stops people pasting secrets into AI chatbots, before the message is sent.

    problem
    People paste API keys and company data into chatbots, and traditional data-loss tools can't see it.
    what I built
    The detector. The safest place to stop a leak is before it leaves the device, so I fine-tuned DistilBERT and exported it to ONNX, small enough to run inside the extension.
    result
    0.89 macro F1 against 0.69 for the best baseline, and prompts never leave the device.

    PyTorch · Hugging Face · ONNX · Chrome MV3

    team repo is private · happy to walk through the code in an interview

    project 03 · capstone · health security

    MedSentry

    Flags hospital device messages that are perfectly valid, but medically impossible.

    problem
    Hospital systems accept forged vitals as long as the message format is correct.
    what I built
    The dataset and evaluation. Real attacks pass format checks, so I built a generator that turns open ICU data into HL7 streams that look valid but are medically impossible, and a harness that scores the detector.
    result
    A realistic test set of 53 patients and 3,395 messages, scored against 5 baselines.

    Python · HL7 v2 · Docker · evaluation

    team repo is private · happy to walk through the code in an interview

    project 04 · research · IoT × ML

    Federated IDS

    Intrusion detection that learns from many networks without anyone sharing their raw traffic.

    problem
    Centralised detection needs everyone's traffic, and breaks on networks it hasn't seen.
    what I built
    Hospitals and factories won't share raw traffic, so the model goes to the data: a multi-encoder DNN plus autoencoder, trained with federated learning across three public IoT datasets (11M+ samples).
    result
    90%+ accuracy on unseen networks against 25–40% for centralised models, under 1% false positives.

    TensorFlow · federated learning · IoT datasets

    code is being cleaned up for a public release
